01

How it works

Data sources connect into the classifier — which is the core's policy control (an extended PCF that authors data-class policy) coupled with data division (UPF steering that splits flows by PCC/PDR rules). Sensitive classes break out to AI inside your perimeter; the rest pass to cloud. No AI sits inside the core network functions.

Sensitive — provided or your own AI, on-prem Non-sensitive — eligible for cloud classifier = policy control ⊕ data division

# sensitive class → AI inside the perimeter (ours or yours)
route data_class: "phi.imaging"
  match: { slice: S-NSSAI-3, dnn: clinical }
  target: local_ai   provider: managed | self
    endpoint: https://ai.local/v1/infer   protocol: grpc
  leave_perimeter: false

# non-sensitive class may use cloud
route data_class: "ops.reporting"   target: cloud_ai   leave_perimeter: true
03

Platform features

Built on a 5G core you own outright, with classification precise enough to enforce data-residency rules — and disciplined enough never to inspect what's inside a packet.

Classifier = core expansion data

  • Policy control (extended PCF)Authors data-class policy from slice (S-NSSAI), DNN/APN, UE group and application ID — the decision brain.
  • Data division (UPF steering)Enforces it as PCC/PDR rules with UL CL breakout on the data plane — the hands. No payload read.
  • Tunable, versioned policyRefine data-class rules per site, slice or group; tighten residency without touching the access network.
  • No AI inside the NFsHeavy ML stays in the NWDAF / analytics plane and feeds policy back — core stays standards-clean and upgrade-safe.

Two ways to run AI provided or own

  • Managed AI platform (ours)On-prem inference we package and operate, with curated sovereign or open-weight models.
  • Bring your own AIConnect the internal LLM / AI you already run over open REST / gRPC APIs.
  • One routing API, two targetsSwitch or mix providers by data class; sensitive flows stay inside the perimeter either way.

Sovereign control & governance perimeter

  • You own the coreopen5gsEnt runs on your hardware in your perimeter — no third-party cloud core in the data path.
  • Policy-based data governanceResidency and access rules are enforced in the network itself, not left to application discipline.
  • Compliance evidence by designRouting and inference access are logged as a by-product — usable for EU AI Act, HIPAA and data-residency review.

Access-independent & flexible routing

  • Independent of RAN & interfaceGoverns data the same way over 5G, Wi-Fi or wired — no dependency on a specific radio.
  • On-prem, cloud or hybridEach data class routes to local AI, cloud AI, or both — by policy, changeable without re-architecting.
  • Local breakoutAccelerated data plane keeps latency low for real-time inference at the edge.
